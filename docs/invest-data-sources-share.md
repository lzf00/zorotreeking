# 投资看板数据来源说明

> 可直接转发。对应站点：股票实时看板 `/invest`、Wind 深度看板 `/invest/market`、ETF 页 `/invest/etf`。

---

## 一、股票实时看板（`/invest`）

盘中盯盘用的主看板。

| 项目 | 说明 |
|------|------|
| **数据源** | 东方财富公开接口 `push2delay.eastmoney.com`（免费，无需 API Key） |
| **获取方式** | 浏览器约每 60 秒请求自家后端 `/api/market`、`/api/market/sectors`、`/api/market/stocks`、`/api/market/fund`；后端再拉东财，并做短缓存（约 5 秒） |
| **延迟** | 约 **1 分钟**（选用 delay 版；实时 `push2` 对服务器 IP 不稳定） |
| **首屏兜底** | 构建时读 Wind 日终快照 JSON；有 JS 后会被实时接口覆盖 |
| **覆盖内容** | A 股指数、板块涨跌、持仓/聚焦个股、基金估值（天天基金 / 东财基金接口） |

### 补充：Wind 深度看板（`/invest/market`）

| 项目 | 说明 |
|------|------|
| **数据源** | Wind（专业终端） |
| **获取方式** | 交易日约 **15:30** 服务器拉一次，写成静态 JSON 推仓库部署 |
| **性质** | **不是实时**，适合复盘，不适合盘中盯盘 |

## 二、ETF 部分（`/invest/etf`）

同一页有两套数据：**盘中实时** + **日终三因子模型**。

### 1. 盘中实时成交额

| 项目 | 说明 |
|------|------|
| **现价 / 涨跌 / 今日成交额** | 东方财富 `push2delay`（约 1 分钟延迟） |
| **昨日全天成交额（对比基准）** | 优先腾讯财经 `web.ifzq.gtimg.cn`；失败再用东财日 K |
| **获取方式** | 前端约每 60 秒请求 `/api/market/etf` |
| **用途** | 宽基 ETF 池「今日成交 vs 昨日全天」对比 |

### 2. 三因子「国家队」监测（日终模型）

综合概率 = **量能 50%** + **方向 20%** + **份额 30%**

| 因子 | 权重 | 数据源 |
|------|------|--------|
| 量能 | 50% | 腾讯财经 K 线（日成交 ÷ 20 日均量） |
| 方向 | 20% | 腾讯财经 K 线（逆市护盘等特征） |
| 份额 | 30% | akshare 拉上交所 / 深交所官方份额（一级市场申赎） |

| 项目 | 说明 |
|------|------|
| **产出** | 静态 JSON / HTML 快照挂到站上，**不是**秒级推送 |
| **节奏** | 交易日约 **15:15** 先出量能+方向；约 **19:30** 份额更新后再补全三因子 |
| **注意** | 份额盘后才更新；盘中运行会用最近可用交易日 |

信号分级（示意）：≥70% 高确信｜50%–70% 中等｜&lt;50% 正常。

## 三、一句话对照

| 模块 | 数据从哪来 | 怎么更新 |
|------|------------|----------|
| 股票实时看板 | 东财 delay 公开行情 | 自家 API 轮询，约 1 分钟延迟 |
| Wind 深度看板 | Wind | 交易日 15:30 日终快照 |
| ETF 盘中成交 | 东财现价/成交额 + 腾讯昨日基准 | 约 60 秒刷新 |
| ETF 三因子 | 腾讯 K 线 + 交易所份额（akshare） | 日终模型，非实时行情 |

---

## 四、使用注意（分享时建议带上）

1. **公开行情接口，非交易所官方实时源**；延迟约 1 分钟，偶发上游限流或空响应时看板会短暂用缓存/兜底。
2. **实时链路不依赖付费 Key**；Wind 只服务日终深度看板，不参与盘中实时。
3. **三因子是启发式监测模型**，不是投资建议；份额因子依赖交易所盘后数据。
4. 接口地址、字段可能随东财/腾讯调整，属免费公开接口的常见风险。
